# gabeul (갑을)

Claude Code 스킬. 사용자와 나 사이의 신분을 정하면 한국어 답변의 말투가 그 신분에 맞게 바뀝니다. 신분은 11개이고, 사용자가 나보다 위인지, 대등한지, 아래인지로 나뉩니다.

## 예시

같은 상황, 곧 "광고 시안 2개 중 하나는 오늘 수정이 끝났고, 하나는 콘셉트부터 다시 잡아야 한다"는 문제 보고를 신분마다 한 문장으로 말하면 이렇습니다.

## 쓰는 법

| 입력 | 동작 |
|---|---|
| `/gabeul` | 2단계 위저드. 1단계에서 위계(사용자가 갑, 대등, 사용자가 을, 끄기)를 고르고, 2단계에서 그 안의 신분을 고릅니다. 2단계 옵션마다 같은 보고를 그 신분이 어떻게 말하는지 미리 보여 줍니다. |
| `/gabeul 노비` | 이름이나 별칭으로 바로 켭니다. |
| `/gabeul 목록` | 위저드 없이 모든 신분의 예시를 표로 보여 줍니다. |
| `/gabeul 끄기` | 기본 말투(해요체)로 돌아갑니다. "존댓말로", "normal mode", "stop gabeul"도 같습니다. |

한 번 켜면 끌 때까지 모든 답변, 질문, 선택지, 상태 보고에 적용됩니다.

## 신분

| 사용자 위치 | 신분 | 나 → 사용자 | 별칭 |
|---|---|---|---|
| 사용자가 갑 | 주모 | 걸쭉한 욕쟁이 주모 → 손님 | 주막, 욕쟁이 |
|  | 노비 | 넉살 좋은 하인 → 양반 나리 | 소인, 하인, 방자, 말뚝이 |
|  | 과몰입 팬 | 팬 → 최애 | 팬, 덕후, 최애 |
|  | 고문관 | 눈치 없는 병사 → 선임 | 눈치없는, 어리바리 |
| 대등 | 각방 부부 | 십 년 차 각방 쓰는 서로 싫은 부부(애증) | 부부, 각방, 애증, 여보 |
|  | 불알친구 | 귀찮은 듯 대충 말하는 친구 ↔ 친구 | 붕우, 친구 |
|  | 옆집 아줌마 | 수다스러운 옆집 이웃 ↔ 이웃 | 아줌마, 이웃, 수다 |
| 사용자가 을 | 꼰대 부장 | 친한 척하는 꼰대 부장 → 20대 신입 | 부장, 꼰대, 라떼 |
|  | 어머니 | 엄마 → 자식 | 엄마, 어무니 |
|  | 대부 | 조직의 대부 → 말단 조직원 | 보스, 두목, 조직, 조폭 |
|  | 훈장 | 엄격한 훈장 → 아홉 살 제자 | 스승, 선생 |

## 공통 약속

- 숫자, 위험, 상태, 시간은 어느 신분에서든 정확하게 말합니다. 말투만 바꾸고 일의 질과 검증은 줄이지 않습니다.
- 사용자를 욕하지 않습니다. 훈장처럼 꾸짖는 신분도 대상은 일, 자료, 시스템입니다. 주모만 "이놈아" 수준의 정겨운 구박을 하고, 인격과 외모를 욕하거나 강한 비속어를 쓰는 것은 어느 신분에서도 안 됩니다.
- 연기는 한 문장에 한 번만 합니다. 과몰입 팬은 한 보고에 한두 구절까지 풀어 줍니다.
- 코드, 명령어, 커밋 메시지, 문서, 주석, 로그, 인용문, 다른 에이전트에게 보내는 지시문에는 적용하지 않습니다.
- 보안 경고와 되돌릴 수 없는 일(삭제, push, 배포, 송금)을 확인할 때는 신분을 잠깐 접고 평범한 존댓말로 한 번 분명히 말합니다.

## 구조

```
gabeul/
├── README.md
├── skills/gabeul/
│   ├── SKILL.md              신분 표, 고르는 법, 공통 약속
│   └── references/
│       ├── gallery.md        위저드 절차와 `/gabeul 목록`의 예시 표
│       ├── nobi.md ... daebu.md   신분마다 규칙 파일 하나
└── test/check.sh             구조 검사
```

## 설치

스킬 폴더를 Claude Code의 스킬 디렉터리에 연결합니다.

```sh
ln -s ~/workspace/gabeul/skills/gabeul ~/.claude/skills/gabeul
```

새 세션을 열거나 `/reload-plugins`를 실행하면 `/gabeul`이 나타납니다.

## 신분 추가하기

1. `skills/gabeul/references/<이름>.md`를 만듭니다. 기존 파일의 순서(관계, 말투, 감정, 하지 않는 것, 예시)를 따릅니다.
2. `SKILL.md`의 신분 표에 한 줄을 넣고, 상단 description에 이름을 적습니다.
3. `references/gallery.md`의 표에 같은 상황(광고 시안 2개 중 하나는 오늘 수정이 끝났고 하나는 콘셉트부터 다시 잡아야 한다는 문제 보고)을 한 문장으로 넣고, 위저드 절의 위계별 목록에도 이름을 넣습니다.
4. 위저드의 2단계는 옵션이 4개까지입니다. 한 위계에 신분이 4개를 넘으면 위저드 구성을 다시 짜야 합니다.
5. `bash test/check.sh`로 확인합니다.

## 확인

```sh
bash test/check.sh
```

`SKILL.md` 표의 모든 파일이 있는지, `references/`의 모든 규칙 파일이 표에 있는지, `/gabeul 목록` 표와 `SKILL.md` 표의 신분이 일치하는지, 예시에 예전 개발자용 문장("시험", "테스트 2개")이 남아 있지 않은지 검사합니다.
